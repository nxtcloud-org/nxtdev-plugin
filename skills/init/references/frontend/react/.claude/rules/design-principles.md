# 설계 원칙

## 순수성 (공식 규칙)

- 컴포넌트는 순수 함수: 같은 입력 → 같은 출력
- 렌더링 중 side effect 금지
- 로컬에서 생성한 변수/배열은 변경 가능 (로컬 mutation OK)
- StrictMode로 불순한 컴포넌트 감지 (개발 중 2번 호출)

## 선언적 UI (공식 패턴)

- UI 상태를 명령형으로 조작하지 않기 (DOM 직접 수정 금지)
- 가능한 모든 시각적 상태를 정의하고, state 변경으로 전환
- 중복 상태 금지: 다른 state에서 계산 가능한 값은 렌더 중 계산

## 구조

- 동시에 실행되지 않는 코드는 분리된 컴포넌트로
- 함께 수정되는 파일은 같은 디렉토리에 (도메인별 분류)

## 가독성

- 복잡한 조건에 변수명 부여 (맥락 축소)
- 삼항연산자 중첩 금지, early return 사용
- 매직 넘버/스트링은 상수로 추출

## 예측 가능성

- 이름 겹침 방지 (같은 이름 = 같은 동작)
- 반환 타입 통일 (같은 종류 함수는 같은 형태)
- 함수 시그니처로 예측 불가능한 부작용은 명시화

## 결합도

- 과도한 공통화 금지 (동작이 다르면 중복 허용)
- 3번 반복되기 전까지 추상화하지 않음

## 이벤트 핸들러 vs useEffect

- 사용자 상호작용에 의한 로직 → 이벤트 핸들러
- 외부 시스템 동기화 → useEffect
- "이 코드가 특정 상호작용 때문에 실행되나?" → Yes면 이벤트 핸들러
